1. Enterprise UI Architecture with SAP Fiori & UI5 Web Components

The Concept

Instead of relying on heavy SPA frameworks, this platform is built on standard W3C Web Components via @ui5/webcomponents v2, implementing official SAP Fiori floorplans directly in vanilla TypeScript.

Architectural Rationale

  • Zero Framework Lock-in: Runs natively in the browser without virtual DOM diffing overhead or framework upgrade cycles.
  • Proven Enterprise Floorplans: Employs the List Report (multi-criteria filter bar, high-density table, sorting, pagination) and Object Page (sticky header metrics, KPI blocks, segmented tab containers).
  • Accessibility (WCAG 2.1 AA): Native screen reader support, keyboard traversal, and standard ARIA roles built into every UI5 component.

Implementation

// Dynamic Visual Theme Switching
import { setTheme } from '@ui5/webcomponents-base/dist/config/Theme.js';

export class ThemeStore extends Store<ThemeState> {
  public toggleTheme(): void {
    const isDark = !this.state.isDark;
    setTheme(isDark ? 'sap_horizon_dark' : 'sap_horizon');
    document.documentElement.classList.toggle('dark', isDark);
    this.setState({ isDark, themeName: isDark ? 'Dark Theme' : 'Light Theme' });
  }
}
Key Takeaway: Web Components provide an enterprise-grade design system with native performance, built-in accessibility, and zero framework churn.

2. Reactive State Management & Decoupled Frontend Patterns

The Concept

A reactive, lightweight state management layer built with the Observer and Pub/Sub patterns in under 150 lines of TypeScript, replacing heavyweight external libraries.

Architectural Rationale

  • Discrete Domain Stores: State is modularized into appStore (documents, filters, upload queue), backendStore (active mode, latency), themeStore (visual theme), and i18nStore (localization dictionaries).
  • Fine-Grained Subscriptions: Views subscribe only to the state slices they consume, eliminating full-page DOM thrashing.
  • Automatic Lifecycle Management: The base Component class tracks subscriptions with track(unsub) and cleans up during unmount() to prevent memory leaks.
// src/main/frontend/core/store.ts
export class Store<T> {
  private _state: T;
  private _listeners = new Set<(state: T) => void>();

  constructor(initialState: T) { this._state = Object.freeze({ ...initialState }); }
  public getState(): T { return this._state; }
  public setState(partial: Partial<T>): void {
    this._state = Object.freeze({ ...this._state, ...partial });
    for (const listener of this._listeners) { listener(this._state); }
  }
  public subscribe(listener: (state: T) => void): () => void {
    this._listeners.add(listener);
    return () => this._listeners.delete(listener);
  }
}
Key Takeaway: Minimalist observable state stores combined with structured component lifecycles yield predictable, leak-free reactivity without framework bloat.

3. Pluggable Backend Gateway & Driver Adapter Pattern

The Concept

A unified Gateway Facade (BackendGateway) mediates all data and AI requests, dispatching to swappable adapter drivers adhering to the BackendAdapter interface.

Architectural Rationale

  • Standalone Execution: The MockBackendAdapter enables full-fidelity frontend execution (offline demo sandboxes, CI test suites) with local storage persistence and simulated AI latency.
  • Hot-Swapping at Runtime: Users can toggle between Mock and Live Spring Boot REST modes in real time without refreshing or losing state.
  • Protocol Isolation: UI views never execute HTTP calls directly, ensuring that changes to network protocols do not ripple through presentation code.
// src/main/frontend/services/backend/adapter.ts
export interface BackendAdapter {
  readonly mode: BackendMode;
  listDocuments(query?: DocumentListQuery): Promise<DocumentListResult>;
  getDocument(guid: string): Promise<DocumentRecord>;
  uploadDocument(payload: DocumentUploadPayload): Promise<DocumentRecord>;
  overwriteDocument(guid: string, payload: DocumentUploadPayload): Promise<DocumentRecord>;
  deleteDocument(guid: string): Promise<boolean>;
  getVersionHistory(guid: string): Promise<DocumentVersionSnapshot[]>;
  rollbackVersion(guid: string, targetVersion: number): Promise<DocumentRecord>;
  summarizeDocument(guid: string, model: 'llama' | 'mistral'): Promise<SummaryRecord>;
  chat(payload: ChatRequestPayload): Promise<ChatResponseResult>;
  getHealth(): Promise<HealthStatusResult>;
}

Communication Protocol Architecture: Why HTTP/REST Over WebSockets (ADR-004)

The platform deliberately uses stateless HTTP/REST (JSON & Multipart) for client-to-backend communication, coupled with a client-side TypedEventBus (anchored to a detached DOM Comment node). Persistent WebSockets are omitted by design: stateless HTTP avoids persistent socket overhead, eliminates sticky load balancing requirements, and handles Keycloak OIDC bearer token injection natively per request. The Send Task in the Camunda BPMN workflow (Broadcast Ingestion Status) is fulfilled directly on the client through the in-memory event bus and reactive appStore. (Read Full Communication Architecture ADR-004 →)

Key Takeaway: Abstracting backend access behind a typed adapter contract makes applications testable, resilient to network outages, and easy to run in standalone environments.

4. Multi-Model Large Language Model (LLM) Orchestration & Comparative Benchmarking

The Concept

Pairing two specialized local Large Language Models (LLMs: Ollama Llama 3.3 70B and Mistral Large 2411) with distinctive analytical personas, reinforced with Google Gemini cloud fallback via @google/genai Software Development Kit (SDK).

Architectural Rationale

  • Persona Specialization: Llama acts as an academic researcher performing deep structural and methodological critiques; Mistral acts as an executive technology director highlighting actionable takeaways.
  • Cloud Fallback Resilience: When local Ollama hardware is unavailable or overloaded, requests cascade automatically to server-side Google Gemini Flash via @google/genai.
  • Thread-Safe Concurrency: Both models can be triggered simultaneously without race conditions, tracking execution duration and generation telemetry independently.
// Parallel Regeneration in appStore.ts
public async regenerateSummary(guid: string, model: 'llama' | 'mistral'): Promise<void> {
  this.setSummaryLoading(guid, model, true);
  try {
    const record = await backendGateway.summarizeDocument(guid, model);
    this.updateDocumentSummary(guid, model, record);
  } finally {
    this.setSummaryLoading(guid, model, false);
  }
}
Key Takeaway: Dual-persona model orchestration provides multifaceted insights, while parallel execution and cloud fallback guarantee both performance and reliability.

5. Retrieval-Augmented Generation (RAG) & Vector Database Architecture

The Concept

Grounded conversational document Q&A built on Qdrant vector database similarity indexing, semantic chunking, Hierarchical Navigable Small World (HNSW) graphs, and verifiable source attribution.

Architectural Rationale

  • Sliding-Window Chunking: Partitions document text into 500-token chunks with 50-token contextual overlaps to preserve sentence boundaries.
  • Dense Cosine Similarity: Uses Qdrant HNSW indexing in the library_embeddings collection for sub-10ms top-$k$ nearest neighbor retrieval.
  • Anti-Hallucination Controls: Prompts restrict models to retrieved excerpts only, requiring direct citation anchors.
  • Interactive Citation Drawer: Clicking citation markers in responses highlights the exact verbatim excerpt in the source document alongside relevance confidence scores.
Key Takeaway: Vector Retrieval-Augmented Generation (RAG) with interactive source attribution transforms speculative LLM text into an auditable research instrument.

6. Camunda Business Process Model and Notation (BPMN 2.0) Workflow Orchestration

The Concept

Modeling and executing document ingestion, Optical Character Recognition (OCR) extraction, vectorization, and dual AI summarization as an auditable enterprise Business Process Model and Notation (BPMN 2.0) process.

Architectural Rationale

  • Long-Running Reliability: Handles asynchronous multi-step extraction with built-in retry policies (R3/PT10S) for network resilience.
  • Human-in-the-Loop Gateway: Routes low-confidence metadata extractions to a manual review task before vector indexing.
  • Full Auditability: Visualized in-app with an interactive BPMN viewer dialog and executable BPMN 2.0 XML inspector.
Key Takeaway: Formal BPMN workflow modeling bridges business process governance with technical microservice task execution.

7. Domain-Specific Parsing & Abstract Syntax Tree (AST) Metadata Engineering (LaTeX / BibTeX)

The Concept

A specialized lexer and Abstract Syntax Tree (AST) tokenizer that parses, validates, and generates standardized LaTeX BibTeX entries across 14 metadata fields.

Architectural Rationale

  • Schema-Driven Dynamic Forms: Adapts form layouts dynamically depending on publication type (@article, @book, @inproceedings, etc.).
  • Bidirectional Conversion: Translates structured form state into sanitized LaTeX Backus–Naur Form (BNF) notation, handling nested braces and LaTeX accents (e.g. \"{a} → ä).
  • Citation Exports: Provides one-click clipboard copying, .bib file downloads, and formatted academic citations (APA, IEEE, Chicago).
Key Takeaway: Domain-specific format engineering ensures seamless interoperability with academic publishing workflows.

8. Document Versioning, Lineage & Immutable Rollback Architecture

The Concept

An append-only version control architecture combining in-place Globally Unique Identifier (GUID) continuity with immutable historical snapshot archiving and instant rollback.

Architectural Rationale

  • Stable Primary Key Continuity: The document GUID remains constant across revisions, preserving external bookmarks and citation links.
  • Immutable Snapshot Archiving: Captures complete document state, raw BibTeX, text chunks, dual summaries, and physical binary files before any mutation.
  • Non-Destructive Rollback: Reverting to an earlier version restores its contents while incrementing the version counter (e.g. rolling back from v3 to v1 yields v4), maintaining a complete audit trail without data loss.
  • Historical Asset Retrieval: Preserved files can be downloaded directly for any historical version revision.
// Snapshot Interface
export interface DocumentVersionSnapshot {
  version: number;
  timestamp: string;
  action: 'UPLOAD' | 'OVERWRITE' | 'ROLLBACK';
  note: string;
  fileName: string;
  fileSize: number;
  fileType: string;
  bibtex: BibTeXMetadata;
  summaries: Record<string, SummaryRecord>;
  downloadUrl: string;
}
Key Takeaway: Combining stable GUIDs with immutable snapshot archiving provides complete disaster recovery and auditability across document lifecycles.

9. Production-Grade Microservices Topology, Keycloak OIDC (OpenID Connect) & Security

The Concept

A multi-tier containerized architecture orchestrated via Docker Compose, secured with Keycloak OpenID Connect (OIDC) / OAuth 2.0 and Role-Based Access Control (RBAC) under GNU AGPLv3.

Architectural Rationale

  • Tiered Microservices: Spring Boot API Gateway, MongoDB Document Store, Qdrant Vector DB, Ollama LLM server, and Keycloak Identity and Access Management (IAM).
  • Stateless JWT Security: Validates JSON Web Token (JWT Bearer) claims against the personal-library-realm with Spring Security resource server filters.
  • Granular RBAC: Enforces distinct capabilities for LIBRARY_ADMIN, CHIEF_RESEARCHER, and VIEWER roles.
  • Strong Copyleft Compliance: Licensed under GNU Affero General Public License v3.0 (AGPL-3.0-or-later) to protect network user freedom and ensure open-source reciprocity.
Key Takeaway: Decoupled container orchestration combined with standards-based OIDC and RBAC delivers enterprise-grade security and operational maturity.

10. Architecture-as-Code & Automated Visual Documentation Tooling

The Concept

Treating documentation and diagrams as executable code, automatically compiling synchronized visual artifacts across multiple industry formats from single sources of truth.

Architectural Rationale

  • Prevention of Documentation Drift: Running npm run diagrams re-renders all diagrams whenever data models or endpoints change.
  • Multi-Format Outputs:
    • Developers: Mermaid (.mmd) and PlantUML (.puml) for version control and git diffing.
    • Architects: Vector SVG and Draw.io (.drawio) XML for infinite zoom and collaborative editing.
    • Executives & Compliance: Ultra-HD 4K PNGs (via Resvg) and archival multi-page landscape PDFs (via PDFKit).
  • Contract-First OpenAPI: Complete REST API documentation maintained in openapi.yaml with interactive Swagger UI support.
  • Domain Entity Models (ERD): Dedicated Entity-Relationship diagrams and data dictionaries maintained in scripts/generate-entity-diagrams.ts (View Interactive ERD →).
  • System Ontology & Semantic Knowledge Graph: Formal W3C OWL 2, PROV-O, and BIBO ontology with RDF Turtle serialization maintained in scripts/generate-ontology-diagrams.ts (View Interactive Ontology →).
Key Takeaway: Programmatic visual diagram generation keeps documentation evergreen and synchronized with production code.
