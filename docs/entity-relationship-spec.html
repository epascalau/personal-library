2. Core Domain Entities & Database Schemas

2.1 DocumentEntity (Primary Aggregate Root)

  • Storage Engine: MongoDB (documents collection) / TypeScript DocumentRecord
  • Java Package: com.personallibrary.model.DocumentEntity
  • Description: Represents an ingested academic paper, book, or technical document. Acts as the aggregate root for bibliographic metadata, AI summaries, chunked vectors, and version lineage.
Field Name Type Key / Constraint Description
guid UUID Primary Key, Indexed Unique immutable identifier (UUID v4) for the document record.
previousVersionGuid UUID? Foreign Key (Self-Ref) Pointer to the prior version's document GUID if created via overwrite or rollback.
versionNumber Integer Non-Null, $\ge 1$ Current active revision sequence number (e.g. 1, 2, 3).
fileName String Non-Null Original uploaded file name with extension (e.g. attention_is_all_you_need.pdf).
fileSize Long Non-Null, $> 0$ File size in raw bytes (up to 52,428,800 bytes / 50 MB).
fileSizeFormatted String Synthetic Human-readable string representation (e.g. 2.4 MB).
format String Enum Normalized file format (pdf, docx, doc, txt, md, pptx, ppt, xls, xlsx).
uploadDate Instant Non-Null ISO-8601 UTC timestamp of initial file ingestion.
editDate Instant Non-Null ISO-8601 UTC timestamp of latest metadata or content modification.
contentExcerpt String Max 300 chars Initial text excerpt displayed in list views and search cards.
fullContent Text Large String Full plaintext stream extracted from binary files via pdf-parse or text decoders.
chunkCount Integer $\ge 0$ Total number of semantic passages into which the text was partitioned.
tags List<String> Array Categorical topic tags (e.g. ['Deep Learning', 'Transformers']).
sha256Hash String 64 Hex Chars SHA-256 cryptographic digest of the raw physical binary file asset.
uploadedBy String Foreign Key User ID / Username of the authenticated uploader (UserProfile.id).

2.2 BibTeXMetadata (Bibliographic Value Object)

  • Storage Engine: Embedded within DocumentEntity.bibtex and DocumentVersionSnapshot.bibtex
  • Java Package: com.personallibrary.model.BibTeXMetadata
  • Description: Normalized 14-field LaTeX BibTeX citation record generated by an Abstract Syntax Tree (AST) lexer with heuristic extraction.
Field Name Type Key / Constraint Description
bibKey String Synthetic Key Citation key formatted as AuthorYearKeyword (e.g. Vaswani2017Attention).
entryType BibTeXType Enum Standard BibTeX entry classification (article, book, inproceedings, techreport, phdthesis, misc).
title String Non-Null Primary document or article title.
author String Non-Null Canonical list of authors formatted with LaTeX standards (and separated).
year String 4 Digits Publication year (e.g. 2017).
month String? Optional Publication month (e.g. December).
journal String? Optional Journal name for @article entries.
booktitle String? Optional Conference proceedings title for @inproceedings.
volume String? Optional Journal or report volume number.
number String? Optional Issue or serial number.
pages String? Optional Page range (e.g. 5998--6008).
publisher String? Optional Publishing house or distribution organization.
edition String? Optional Publication edition (e.g. 1st Edition).
institution String? Optional Sponsoring research institution for technical reports.
school String? Optional University granting institution for theses.
doi String? Indexed Digital Object Identifier (e.g. 10.1145/3065386).
isbn String? Optional International Standard Book Number.
issn String? Optional International Standard Serial Number.
url String? Optional Persistent HTTP/HTTPS canonical URL.
abstract Text Optional Executive or author-provided research abstract.
keywords String? Optional Comma-delimited keywords.
rawBibTeX Text Formatted String Complete, syntactically valid LaTeX BibTeX definition.

2.3 SummaryRecord (Multi-Model AI Summary)

  • Storage Engine: Embedded map DocumentEntity.summaries (llama, mistral)
  • Java Package: com.personallibrary.model.SummaryRecord
  • Description: Captures LLM-generated summaries and operational telemetry from the Spring AI / Ollama inference pipeline.
Field Name Type Key / Constraint Description
modelKey String Key (llama | mistral) Unique identifier for the foundational model family.
modelName String Non-Null Descriptive display name (e.g. Ollama Llama 3.3 (70B Instruct)).
summaryText Text Markdown Generated abstractive synthesis formatted in GitHub Flavored Markdown.
generatedAt Instant UTC Timestamp Moment when inference completed and was persisted.
durationSeconds Double $> 0$ Total wall-clock generation latency in seconds.
durationFormatted String Synthetic Human-friendly latency string (e.g. 14.2s or 1m 04s).
promptTokens Integer? Telemetry Number of prompt tokens processed by the LLM context window.
completionTokens Integer? Telemetry Number of output tokens generated by the LLM.
temperature Double Constraint Model sampling temperature (0.2 for Llama, 0.3 for Mistral).

2.4 DocumentChunk (Qdrant Vector Embedding Point)

  • Storage Engine: Qdrant Vector Database (personal_library_embeddings collection)
  • Java Package: com.personallibrary.model.DocumentChunk
  • Description: Segmented semantic text passage indexed into high-dimensional vector space for sub-millisecond Approximate Nearest Neighbor (ANN) search.
Field Name Type Key / Constraint Description
id String Point ID (PK) Qdrant point key formatted as {documentGuid}-c{chunkIndex}.
documentGuid UUID Payload Filter (FK) Scopes vector queries strictly to a single document to prevent cross-document context leaks.
chunkIndex Integer $\ge 0$ Zero-based sequence number of the chunk within the document.
text Text ~400–500 chars Paragraph-boundary aligned text passage.
pageNumber Integer $\ge 1$ Physical page number in the source file where the chunk appears.
tokenCount Integer $\approx 100\text{--}150$ tokens Exact token count evaluated by the BPE tokenizer.
denseVector float32[768] 768 Dimensions Dense vector embedding generated by nomic-embed-text or text-embedding-004.
hnswIndex HNSW Node M=16, ef=100 Multi-layer skip graph node indexed using Cosine distance metric.

2.5 DocumentVersionSnapshot (Immutable Audit Lineage)

  • Storage Engine: Embedded array DocumentEntity.versionHistory
  • Java Package: com.personallibrary.model.DocumentVersionSnapshot
  • Description: Preserves an exact, immutable state snapshot of a document prior to an in-place version overwrite or non-destructive rollback.
Field Name Type Key / Constraint Description
snapshotGuid String Primary Key Unique identifier for the historical snapshot.
versionNumber Integer Historical Sequence Version number archived at the time of the snapshot.
fileName String Non-Null Physical file name archived at this version.
fileSize Long Bytes Size of the physical asset at this version.
fileSizeFormatted String Derived Human-readable formatted size (e.g. "42 B").
format String Enum File format extension.
physicalFilePath String Path Server disk path to the version-isolated preserved asset (.../v{version}/{filename}), independent of the current active file.
savedAt Instant UTC Timestamp Moment the snapshot was archived.
bibtex BibTeXMetadata Embedded Structured BibTeX metadata active at this version.
bibtexRaw Text LaTeX BibTeX Complete formatted BibTeX metadata active at this version.
summaries Map<String, SummaryRecord> Keyed by model (llama, mistral) Dual-model AI summary state active at this version.
contentExcerpt String Excerpt Text excerpt active at this version.
fullContent Text? Plain Text Complete text stream archived for non-destructive restoration.
chunksCount Integer Count Number of chunks vectorized at this version.
note String Audit Note Contextual explanation of why the snapshot was archived (overwrite vs. rollback).

4. Database Indexing Strategy

  1. MongoDB BSON Indexes:

    • { guid: 1 } — Unique primary key index.
    • { uploadDate: -1 } — Reverse chronological index for List Report sorting.
    • { "bibtex.doi": 1 } — Sparse lookup index for digital object identifiers.
    • { "tags": 1 } — Multi-key index for faceted tag filtering.
    • { "fileName": "text", "title": "text", "author": "text" } — Full-text search index.

  2. Qdrant HNSW Graph Indexing:

    • Distance Metric: Cosine
    • Dimensionality: 768
    • M: 16 (Number of edges per node in the graph layers).
    • efConstruct: 100 (Search depth during index building).
    • Payload Index: { "documentGuid": "keyword" } — Enables query-time filtering without post-search overhead.
