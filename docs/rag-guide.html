1. Architectural Overview: Why RAG is Essential

Large Language Models (LLMs) such as Llama 3.3 (70B Instruct) and Mistral Large possess extensive generalized knowledge. However, they suffer from two critical enterprise boundaries:

  • Knowledge Cutoffs & Hallucinations: Models cannot reliably recall internal, domain-specific, or recently updated enterprise documents.
  • Context Window & Attention Degradation: While modern models support large context windows, dumping entire 500-page book libraries into an LLM request causes prompt saturation, prohibitive latency, high memory pressure, and "lost-in-the-middle" attention dropouts.

Retrieval-Augmented Generation (RAG) solves this by decoupling knowledge storage from reasoning capability. Instead of forcing the LLM to memorize the entire corpus, we store the documents in a specialized dual-database topology: MongoDB as the authoritative document repository, and Qdrant as the high-dimensional vector retrieval engine.

2. The Wizard of Oz Case Study

To understand every transformation with complete clarity, let us trace a real paragraph from Chapter 1 ("The Cyclone") of L. Frank Baum's classic masterpiece The Wonderful Wizard of Oz (1900):

“Dorothy lived in the midst of the great Kansas prairies, with Uncle Henry, who was a farmer, and Aunt Em, who was the farmer's wife. Their house was small, for the lumber to build it had to be carried by wagon many miles. There were four walls, a floor and a roof, which made one room; and this room contained a rusty looking cookstove, a cupboard for the dishes, a table, three or four chairs, and the beds.” — L. Frank Baum, The Wonderful Wizard of Oz (1900), Chapter 1

Text Statistics: 348 characters, 69 words, 1 paragraph. Let us examine how this raw prose becomes structured numbers, searchable vectors, and grounded AI answers.

3. What Are Tokens? Sub-word Tokenization

Computers and neural networks do not read letters, words, or sentences. They operate exclusively on discrete integers. The transformation of raw strings into numerical units is called Tokenization.

Modern AI systems utilize Byte-Pair Encoding (BPE) or WordPiece. Instead of splitting strictly on whitespace (which fails on rare or compound words), BPE breaks text into frequent sub-word sequences:

Dorothy#14820
lived#5829
in#287
the#262
midst#27192
of#286
great#1049
Kansas#14902
prair#28411

Uncle#13910
Henry#8712
farmer#8912
cook#6421
stove#19401

Key Token Rules:

  • Common words (e.g., Dorothy, lived, farmer) are single tokens.
  • Uncommon or inflected words (e.g., prairies) are segmented into sub-word tokens: prair + ies.
  • In the English language, 1 token ≈ 4 characters (or ≈ 0.75 words).
  • The 69-word Wizard of Oz passage translates into exactly 84 tokens.

4. What Are Embeddings? Dense Vector Coordinates

While tokens turn words into integers, integer IDs carry no intrinsic semantic meaning. Token #14902 (Kansas) and Token #28411 (prairies) have no mathematical relationship simply because their IDs are distant numbers.

To capture meaning, we pass the token sequence through an Embedding Model (such as nomic-embed-text or text-embedding-004). The embedding neural network maps the sequence into a dense continuous vector in a high-dimensional mathematical space:

v = EmbeddingModel("Dorothy lived in the midst of the great Kansas prairies...")
v = [ +0.0412, -0.0891, +0.1205, +0.0034, ..., -0.0718 ] ∈ ℜ768
||v|| = √(∑ vi2) = 1.0   (Normalized unit vector)

Each dimension in this 768-dimensional space represents a latent semantic concept discovered during pretraining: geographical landscapes, human relationships, architecture, rustic living, agricultural tools, etc.

5. Cosine Hyperspace Geometry & Relevance Scoring

The profound power of embeddings is that semantic similarity equals geometric proximity. When two passages share related meanings, their vectors point in nearly the same direction in hyperspace.

We measure this angle using the Cosine Similarity metric:

cos(θ) = (u • v) / (||u|| ||v||) = ∑(ui × vi) ∈ [-1.0, +1.0]

Consider what happens when a user asks a question:

Vector / Concept Sample Content Cosine Similarity cos(θ) Semantic Interpretation
vquery “Where did Dorothy live and what was her house like?” 1.000 Self-reference baseline
vchunk0 (Kansas) “Dorothy lived in Kansas prairies... house was small, four walls, one room...” 0.892 (89.2%) High Semantic Match • Direct match for location & architecture
vchunk12 (Emerald City) “The guardian of the gates unlocked the spectacles with a golden key...” 0.314 (31.4%) Low Match • Unrelated characters and scenery, discarded by Top-K filter

6. Database Decomposition: MongoDB vs. Qdrant

Key Takeaways:

  • MongoDB is the System of Record. It guarantees ACID properties for full text, version history, BibTeX metadata, and LLM summary caches.
  • Qdrant is the Vector Engine. It uses a Hierarchical Navigable Small World (HNSW) graph index to search over millions of chunks in under 3 milliseconds.

8. The End-to-End RAG Execution Cycle

When a researcher uses the SAP UI5 Web Components-based UI to ask a question, the application executes a seamless 4-step choreography:

  1. Query Vectorization: The user enters “Where did Dorothy live and what was her home like?”. The system tokenizes this into 11 tokens and computes vector v_query via nomic-embed-text.
  2. HNSW Vector Search in Qdrant: Qdrant runs cosine distance calculations against all chunks belonging to documentId: "doc-oz-1900". Chunk #0 surfaces with a 0.892 (89.2%) similarity score.
  3. Augmented Prompt Assembly: The backend constructs an augmented prompt containing strict system instructions, the retrieved chunk context, and the user's question:
    [SYSTEM INSTRUCTION]
    You are an enterprise research assistant. Answer the user question strictly using the provided context. Always cite the exact chunk index.

    [RETRIEVED CONTEXT - CHUNK 0 (Relevance: 89.2%)]:
    "Dorothy lived in the midst of the great Kansas prairies... house was small, four walls, a floor and a roof, one room..."

    [USER QUESTION]:
    Where did Dorothy live and what was her home like?
  4. Llama 3.3 (70B) Inference & Citation Streaming: The LLM reads the verified context and streams tokens back to the SAP Fiori UI via Server-Sent Events (SSE):
    “Dorothy lived in the midst of the great Kansas prairies with Uncle Henry and Aunt Em. Her home was a small, one-room wooden house containing four walls, a floor, a roof, a rusty cookstove, a cupboard, a table, chairs, and beds.” 🔗 Grounded in Citation: [Chunk 0 • Chapter 1: The Cyclone]

9. Implementation in Spring Boot & Express Gateway

In our enterprise codebase, this architecture is implemented in production-grade services:

  • Spring Boot 4.1.1 (Java 21): RagService.java handles semantic chunking (500 tokens / 100 token overlap), calls EmbeddingModel, and interacts with Qdrant via gRPC (port 6334) through QdrantVectorStoreAdapter.java.
  • Express 4.21 Gateway (Node.js 22): server.ts provides proxy routes (/api/v1/chat, /api/v1/documents/:guid/chat, /api/v1/documents/:guid/summarize) and handles vector cosine distance search.
  • SAP UI5 Web Components-based UI: ObjectPageView.ts renders the interactive Chat & RAG Assistant tab, displaying real-time streaming tokens, latency telemetry, and interactive chunk citation cards.
